# 微信插件绑定与消息处理升级说明（待发布）

本文说明本次发布新增或调整的特性、合入的问题修复，以及用户需要关注的配置和使用变化。当前代码版本为 `3.0.0-beta-1`，内容截至 2026-11-09；后续默认值调整单独标明，不代表当前版本已经启用。

## 一、新增与调整的特性

### 1. 提前适配微信绑定 PIN 校验

**后续微信将要求绑定时输入手机微信显示的 PIN 码，需要及早适配这一交互。** 本次插件已支持提示用户输入 PIN 并继续完成绑定。安装器、登录页面及其他集成登录流程的产品，都需要确保用户能够看到提示、输入 PIN 并提交，完成整个绑定过程。

现在可以打开以下配置，强制请求弹出 PIN 校验，用于提前验证适配情况：

```bash
openclaw config set 'channels["openclaw-weixin"].verifyPin' true --strict-json
```

修改后使用新的登录进程重新发起绑定；如果登录由 Gateway 发起，先完整重启 Gateway。实际是否进入 PIN 校验，以微信服务端返回为准。`verifyPin` 当前默认 `false`，关闭它不能阻止服务端要求 PIN。

当前插件通过终端接收 PIN，Gateway 页面尚无对应的提交入口，页面集成需要补齐这一交互。

### 2. 增加实名绑定流程，后续将默认开启

**当前实名流程入口默认关闭，后续计划默认开启，会改变用户的登录交互。**

| 阶段 | 配置与用户体验 |
| --- | --- |
| 当前版本 | `promptBindOwner` 默认 `false`，直接展示 Bot 绑定二维码。 |
| 当前手动开启，或后续默认开启后 | 先询问连接本人还是他人的微信 ClawBot，再进入对应的绑定步骤。 |

开启后的流程为：

- **连接本人 Bot：** 回车或选择 Y，直接展示 Bot 绑定二维码。
- **连接他人 Bot：** 选择 N，操作者先用本人微信扫码完成实名授权；通过后，再由实际连接用户扫描 Bot 绑定二维码。

可以提前开启，验证新的交互流程：

```bash
openclaw config set 'channels["openclaw-weixin"].promptBindOwner' true --strict-json
```

当前输入选择依赖终端。安装器和登录页面需要为本人/他人选择、实名授权二维码展示及授权等待提供相应交互。**后续默认开启的是流程入口；本人绑定仍直接进入 Bot 扫码，选择他人绑定才需要实名授权。** 本次文档更新不改变当前默认值，也不指定后续切换日期。

## 四、配置项及使用影响

### 1. 本次新增配置

以下配置名均相对于 `channels["openclaw-weixin"]`。例如 `verifyPin` 的完整路径为 `channels["openclaw-weixin"].verifyPin`。

| 配置项 | 当前默认值 | 作用与影响 |
| --- | --- | --- |
| `verifyPin` | `false` | 打开后强制请求 PIN 校验，便于提前适配微信后续的绑定要求。实际校验由服务端决定。 |
| `promptBindOwner` | `false`；后续计划默认 `true` | 打开后增加本人/他人选择；选择他人时先实名授权，再扫码绑定。会改变登录交互流程。 |
| `errorNotices` | `false` | 显式设为 `true` 后发送新增的失败提示。关闭时仍记录错误，其他正常消息继续处理。 |
| `mediaDownload.timeoutMs` | `0`，毫秒 | 单次下载总时限；`0` 表示不限，正数表示超时后中止，可能影响长时间下载。 |
| `mediaDownload.idleTimeoutMs` | `30000`，毫秒 | 等待响应或连续没有数据的时限；收到有效数据后重新计时。网络停顿较长时可调大，必须大于 `0`。 |
| `quoteCache.mediaStorage.mode` | `"managed"` | `managed` 沿用原受管目录；`inbound` 使用宿主通用目录；`custom` 使用独立目录。影响缓存文件位置和清理方式。 |
| `quoteCache.mediaStorage.directory` | 未设置 | 选择 `custom` 时必填，填写专供插件使用、可写的绝对路径。切换目录不会自动搬迁旧文件。 |
| `acctwebBaseUrl` | `https://weixin110.qq.com` | 实名接口源站，供特定部署使用；不修改 Bot 取码或 CDN 地址。 |
| `acctwebProxy` | 未设置，直接访问 | 仅代理实名授权相关请求，不代理全部微信消息及媒体流量。 |

这些开关和下载、缓存策略按微信渠道生效。`acctwebBaseUrl`、`acctwebProxy` 另支持 `accounts["<accountId>"]` 下的账号级覆盖。修改配置后重启相关进程；绑定配置需要重新发起登录才能验证。

### 2. 相关已有配置的影响

| 配置 | 与本次发布的关系 |
| --- | --- |
| `messages.inbound.byChannel["openclaw-weixin"]` | 微信专属合并窗口，单位为毫秒。正数开启合并，设为 `0` 明确关闭；可用 `3000` 验证连续图片场景。 |
| `messages.inbound.debounceMs` | 未配置微信专属窗口时使用这个全局值。已有全局正数配置的部署，升级后也可能启用微信消息合并。 |
| `quoteCache.enabled` 及保留期、容量配置 | 控制引用缓存及历史附件的可用范围，不控制待处理消息恢复。下载时长不限，也不会取消文件及缓存大小限制。 |
| 宿主 `attachments.ttlHours` | 宿主清理可能提前删除位于 inbound 下的附件。需要避开该清理时，可使用 inbound 之外的独立缓存目录。 |
| `replyProgressMessages` | 原有工具进度提示，默认开启，与新增的 `errorNotices` 独立。 |
| `routeTag` | 原有环境路由配置，本次扩展到相关接口请求；普通用户无需配置测试路由。 |

消息恢复自动生效，不需要额外开关。缓存目录和清理策略的详细配置见[引用消息本地缓存说明](quote-cache_zh_CN.md)。

## 五、升级与集成时重点关注什么

1. **优先适配 PIN 输入。** 用 `verifyPin: true` 提前验证“扫码、展示 PIN 提示、输入并提交、完成绑定”的完整链路，尤其检查安装器和页面登录入口。
2. **提前适配实名交互。** 当前可用 `promptBindOwner: true` 验证本人/他人选择和实名授权流程，为后续默认开启做好准备。
3. **核对合并与提示的配置。** 合并会改变消息成轮方式和图片等待时间；失败提示需要显式开启。已有全局合并窗口也需要检查。
4. **验证长时间下载与重启恢复。** 持续有数据的下载不应在 30 秒时失败；重启后的已中断任务应先确认执行结果，再决定是否重发。升级或回退前保留账号及消息状态备份。
